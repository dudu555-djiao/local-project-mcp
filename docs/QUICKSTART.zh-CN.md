# 从下载安装到第一次成功读取和修改

项目现名“本地项目助手 / Local Project MCP”；当前已发布的 beta.1 安装包和界面仍显示旧名“本地资料助手”，功能相同。本次更名无需重新安装。

本教程适用于 macOS 14 或更新版本、Apple Silicon（M 系列芯片）。点击 Mac 左上角“关于本机”可查看系统与芯片。

## 1. 下载并打开

- 在 GitHub 仓库的 **Releases** 下载 `LocalReader-0.2.0-beta.1-macos-arm64.zip`；不要选“Source code”，那是开发者源码。
- 解压，把“本地资料助手.app”拖进“应用程序”，然后打开。无需另装 Node、MCP SDK 或 Tunnel 客户端。
- 安装后从“应用程序”打开。下载目录里的解压副本可移到废纸篓，避免系统搜索出现多个同名 app；保留原 ZIP 可用于重新安装。
- 本版没有 Apple Developer ID 签名和公证。macOS 可能阻止首次打开；确认从本项目 Releases 下载并核对 SHA256 后，按“系统设置 → 隐私与安全性”的系统提示允许打开。如果系统或单位策略不允许，停止安装并使用源码方案，不要关闭系统安全保护。
- 校验下载文件：在下载目录运行 `shasum -a 256 LocalReader-0.2.0-beta.1-macos-arm64.zip`，比对该 Release 的 `SHA256SUMS.txt`。

## 2. 选择资料文件夹

在“资料文件夹”页点击 **添加文件夹**，选择具体项目或资料目录。不要选择整个磁盘或整个用户主目录。

添加后使用 **预览**看允许读取的第一层目录。可以添加多个目录，单独停用或移除，也可以 **暂停全部访问**。移除只撤回授权，不删除文件。

所有新加文件夹默认只读。从 0.1 版升级的已有文件夹也默认只读。后面需要直接修改项目时，再为具体文件夹开启 **允许编辑**；模型不能自行开启该选项。

建议第一次只添加一个不含隐私的测试目录，放一个自己写的 README.md，用它完成下面的连接验证。

## 3. 创建自己的 OpenAI Tunnel

打开 [OpenAI Tunnel 设置](https://platform.openai.com/settings/organization/tunnels)。该入口是否可用取决于账号、组织和工作空间权限，未开放时无法靠本软件绕过。

1. 点击 **Create tunnel**。
2. Name 填“本地项目助手”；Description 填“读取本人授权的资料，并按本机权限编辑文本项目”。
3. Organizations 选择自己的 Platform 组织；ChatGPT workspaces 选择你真正使用的 ChatGPT 工作空间。
4. 创建后复制 `tunnel_` 开头的 ID，待会填入软件。

创建或编辑 Tunnel 需要 Tunnels **Read + Manage**；运行和选择 Tunnel 需要 **Read + Use**。组织权限与 ChatGPT 工作空间权限分别检查。不要使用作者、同事或他人的 Tunnel。

## 4. 创建运行密钥

打开 [OpenAI 运行 API keys](https://platform.openai.com/settings/organization/api-keys)，创建供本软件使用的独立密钥。

- 名称可填“Local Project MCP”。如需选择 Project，选择自己的 Platform 项目，这不是上传本地代码。
- Permissions 选择 **Restricted**，只开启 **Tunnels Read + Use**。其他能力保持 None；具体选项名称以平台当前界面为准。
- 如果没有这些选项，先核对组织与账号权限，不要为方便直接使用 Admin key 或打开全部权限。
- 密钥由平台生成，不是自己编的登录密码。复制后直接粘贴进本机软件，不发给别人、不贴到聊天、GitHub 或截图里。

这个 key 用于官方 Tunnel 客户端认证。本软件不调用模型推理 API；它不把 ChatGPT 订阅转换成 API 余额，不承诺 Tunnel 或账户服务免费。

## 5. 在软件中配置并启动

打开 **连接 ChatGPT → 配置连接**：

| 字段 | 填写方式 |
| --- | --- |
| Tunnel ID | 上一步创建的 tunnel_ 开头 ID |
| 运行密钥 | 平台生成的 sk- 开头密钥 |
| 保存在 Mac 钥匙串 | 可选；勾选后下次可复用，否则退出软件后需要重新输入 |
| 组织 ID | 可选；有多个组织且需要明确指定时填自己的组织 ID |
| HTTPS 代理地址 | 需要代理时填自己的 HTTP 代理 URL，例如 http://127.0.0.1:7897；端口必须与自己的代理软件一致 |

保存后点击 **启动连接**。浏览器能上网不代表 Tunnel 会自动使用系统代理；本版需要手动填写代理。

“通道已连通”表示本地客户端就绪且最近 90 秒内有一次成功的 OpenAI 轮询。它不代表网页插件已经创建，也不代表模型已经读取成功。

## 6. 在 ChatGPT 创建个人插件

保持电脑、代理（如有）和本软件运行，打开 [ChatGPT 插件](https://chatgpt.com/plugins)。

1. 点击“添加”→“创建自定义 MCP 服务器”。
2. 名称填“本地项目助手”。描述可填“搜索和读取我授权的文件夹，并在本机允许时编辑文本文件”。
3. 连接选择 **Tunnel / 隧道**，选择或粘贴自己的 Tunnel ID。
4. 身份验证明确选择 **No authentication / 无需身份验证**。不要选 OAuth，也不要选“OAuth 或无需身份验证”。本地访问令牌由客户端携带，账号访问范围由 Tunnel 控制。
5. 阅读风险提示，确认后创建并安装插件。

如果看不到自定义 MCP 或 Tunnel 入口，检查当前工作空间及账号支持范围。软件无法替账号开通该能力。

从旧版升级时，在 ChatGPT 的个人插件设置中刷新工具列表。确认可见 `prepare_edit`、`apply_edit`、`list_changes`、`prepare_restore`；如果旧聊天仍只看到读取工具，新建聊天并重新选择插件。更换软件版本不需要新建一个 Tunnel，也不需要扩大运行 API key 的模型权限。

## 7. 验证读取

在新的 Chat 聊天中通过 @ 或工具选择器选中“本地项目助手”。使用你账号可用的模型；如果希望使用 Pro，请选择 Chat 中可用的 Pro 模型。

先发送：

```text
请使用本地项目助手，调用 server_info 和 list_folders。
列出工具真实返回的状态和已授权文件夹，不要猜测本机内容。
```

然后指定刚才的测试文件夹：

```text
请查看这个测试文件夹的第一层目录，读取 README.md。
引用相对路径和行号，说明是否完整读取以及有没有过滤或截断。
```

软件“访问记录”里出现对应工具调用，模型返回与测试文件一致的内容，才算完成实际读取验证。没有真实工具结果时不要把聊天中的口头确认当成成功。

## 8. 开启编辑并完成第一次修改

先用一个没有隐私的测试文件夹验证。让其中的 `README.md` 包含一行 `演示按钮：提交`，并完成上面的实际读取验证。

1. 在本地项目助手找到该测试文件夹，点击 **允许编辑**，阅读“允许 ChatGPT 编辑这个项目？”提示后确认。授权后按钮变为 **关闭编辑**。这是该文件夹的持续编辑授权，重启后可保留；不会为每次修改弹出一个本地审批窗口。
2. 在 ChatGPT 新聊天中选择插件，要求模型重新读取目标文件，使用返回的 `version`（SHA256）准备局部替换。
3. 先看 `prepare_edit` 返回的预览，核对项目、相对路径和变化内容。生成预览不会修改项目文件。
4. 确认后让模型调用 `apply_edit`，传入刚才返回的 `proposalId`。ChatGPT 对写入工具默认要求确认；阅读客户端的实际确认内容后再允许。
5. 让模型再次调用 `read_file`，在本机打开原文件核对。`apply_edit` 的成功结果、读回内容和原文件一致，才算实际写入成功。

可以分两次发送下面的提示词，先预览，再应用：

```text
请使用本地项目助手，确认我刚开启编辑的测试文件夹。
读取 README.md，使用 read_file 返回的 version，调用 prepare_edit，
把“演示按钮：提交”精确替换成“演示按钮：确认提交”。
先展示真实工具返回的预览和 proposalId，等我确认，不要应用。
```

```text
我确认这个预览。请调用 apply_edit 应用刚才的 proposalId。
成功后重新读取 README.md，报告真实保存结果；失败就说明原因，不要猜测成功。
```

这个过程由网页模型生成具体替换，本地项目助手校验并保存文件。**不需要把方案交给 Codex 再执行一遍，也不会额外调用本机模型。**如果模型只写了一段修改建议，要求它调用真实编辑工具；只在聊天中展示代码不会改变磁盘文件。

提案有效期为 10 分钟，服务重启后失效。关闭编辑、停用文件夹、暂停后再恢复，旧提案仍失效。软件检测到你或其他程序改动过原文件时会拒绝写入；应重新读取并生成预览，不要反复重试旧提案。不要让多个编辑器、Codex 或网页模型同时保存同一个文件，路径和版本检查不等于操作系统沙箱。

日常编辑支持新建 UTF-8 文本文件及必要子目录、最多 20 处精确局部替换。文件最大 2 MiB，单次请求文本总量最多 50 万字符；较大修改要拆分。工具不提供整文件覆盖、删除、移动、任意命令、自动测试、Git 提交或部署。PDF、DOCX、数据库、凭据、符号链接和硬链接不能编辑。

读取结果可能有 `[已隐藏…]` 一类脱敏占位文字。不要让模型把这份读取结果整文件覆盖回去，也不要替换包含隐藏内容的片段。仅在可见原文上做局部编辑，其余原文留在本机；针对隐藏区域或把占位文字写回文件的请求会被拒绝。

## 9. 查看修改记录与恢复

修改前已有文件的原内容会保存在本机私有备份中。在 ChatGPT 中恢复时，先生成内容预览，确认后再应用。

你也可以在本地文件夹卡片点击 **修改历史**，查看记录；可恢复的条目提供 **恢复到修改前**。本机确认窗口显示项目和相对路径，核对当前文件后确认；它不展示完整内容差异。如果需要先比较备份与当前内容，通过 ChatGPT 操作：

```text
请调用 list_changes，列出这个测试文件夹的修改记录。
找到刚才 README.md 的修改，确认 canRestore 为 true，
调用 prepare_restore 生成恢复预览。先展示预览，等我确认。
```

确认后让模型调用 `apply_edit` 应用恢复提案，再读回文件。恢复前会检查当前文件版本；检测到文件已有新的修改时拒绝覆盖，需要由你核对并处理。恢复不会撤销编辑权限。

如果保存结果带有“文件已写入，但记录尚未保存”等警告，先查看原文件和修改历史，不要重复应用同一修改。软件会校验文件和备份后恢复能够确认的记录；标为 `needsReview` 的记录需要人工核对，不能强制恢复。

新建文件的记录标为 `canRestore: false`。本版没有删除工具，不能自动撤销新建文件；需要时由你在本机自行删除。恢复针对本软件保存的旧文件内容，不是整个项目或 Git 历史的回滚。

备份不自动清理，累计上限 200 MiB；满时停止新的写入。备份在 `~/Library/Application Support/LocalReaderMCP/` 的私有数据目录内，不在项目里，也不随升级 app 一起替换。归档或删除前确认恢复需求，不要把这个目录上传 GitHub 或当作反馈附件。

## 10. 日常使用和交给 Codex

之后直接添加新的资料文件夹，按问题让模型搜索并分批读取。

桌面客户端支持相关入口时，可从 Codex 的“新聊天”打开 Quick Chat，选择已有的 ChatGPT 对话，再“添加到 Codex”。如果入口无反应，先保存草稿，退出并重新打开桌面客户端；仍不可用时复制最终方案到正确的 Codex 本地项目。不要依赖共享链接一定能被 Codex 读取。

希望 Codex 继续开发时，让它先核对当前磁盘代码、已有修改、方案假设和测试方法，再按你的明确要求实施。网页插件已经保存的修改会直接出现在本地项目里，避免让两边同时修改同一个文件。本软件可编辑文本，但不运行命令、测试或上线。

## 11. 关闭和升级

- 红色关闭按钮隐藏窗口，菜单栏继续运行；⌘Q 或菜单“退出”会停止服务。
- 休眠、断网、关机期间无法读取或修改。重新联网时 Tunnel 客户端会重试；重新打开软件后仍需点击“启动连接”。
- 升级前退出旧版，用新版替换“应用程序”中的 app。用户设置保存在自己的 Application Support 目录，不放在 app 包内。
- beta.2 安装包尚未发布。以后升级到新名称发行包时，app 改名为“本地项目助手.app”。安装新版后把旧名 app 及多余解压副本移到废纸篓，只保留“应用程序”中的新版；不要同时运行新旧 app。
- 本社区发行版使用 `~/Library/Application Support/LocalReaderMCP/`，首次安装为空白配置，需要由用户主动授权。
- 更名保留原来的数据目录、应用标识和钥匙串服务名。已有授权、连接设置、修改备份及已保存的运行密钥继续沿用，无需重新创建 Tunnel 或密钥；若未保存密钥，仍需在启动连接前输入原密钥。
- ChatGPT 个人插件名称由账户端保存，不会随 app 更名自动更新。可在个人插件设置中手动改为“本地项目助手”并刷新工具列表，不必创建重复插件。
- 从只读版升级不会自动开启编辑；已在新版主动开启的编辑权限会保留。更新后在 ChatGPT 刷新插件工具列表，必要时新建聊天。重启后重新生成待应用提案。
